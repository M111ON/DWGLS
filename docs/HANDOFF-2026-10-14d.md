## 1. ✅ สิ่งที่พิสูจน์แล้ว (วัดบน corpus จริง 61,241×384)

Corpus: `I:/tools/ann/data/memcore/ann_index.jsonl` (e5-small, unit-norm)

### 1.1 HNSW ตกเพราะ lifecycle ไม่ใช่ recall
| | HNSW | anchor+frustum |
|---|---|---|
| recall@10 | **0.99** | 0.94 |
| query | **1.26 ms** | ~16 ms |
| index | ~110 MB | **~256 KB** |
| rebuild on shift | **49.6 s** + 2 instances | regrow **9.9 s**, atomic swap |
| delete (session expiry) | rebuild เพื่อ reclaim | perm regenerate (ms) |
| CAPO shift | rebuild | **relabel 0.006 s** |

เหตุผล: workload เป็น **climate** (distribution shift ทุก ~12h + session delete +
atomicity) → HNSW จ่าย rebuild ทุก cycle *ก่อนถึง query*
อ้างอิงเดิม: `docs/ANN-CLIMATE-CAMPAIGN-2026-09-24.md` §6 (break-even ≈ 6,800 q/rebuild)

### 1.2 anchor regrow = 9.9 s (5× ถูกกว่า HNSW rebuild)
train 9.533 s · assign top-2 0.342 s · perm 0.012 s · **save atomic 0.001 s**
recall@10 = 0.936

### 1.3 CAPO shift โปร่งใสต่อ search — PASS
| piece | keyed on | CAPO cost | rebuild? |
|---|---|---|---|
| anchor decision | **vector** | 0 s | ไม่ (recall 0.9485 → 0.9485 **identical**) |
| frustum descent | address (20736) | 0 s | ไม่ (routes 1000/1000 valid) |
| placement perm | address (MOD-37) | 0.006 s | ไม่ |

**end-to-end serve: top-5 identical 200/200 · relabel+perm 0.006 s vs retrain 9.05 s = 1508×**
(ไม่ restart, ไม่ rebuild)

### 1.4 S4 derived-table — **ตก** (กับดักที่เกือบหลอก)
`ac_build_table` ได้ recall **0.9865 ดูชนะ S5 (0.9485)** — แต่เป็น **collapse artifact**:
ยุบทุก query ไป **1 bucket (56,667/61,241)** → top-2 สแกน **94%** ของ corpus
→ recall สูงเพราะสแกนเกือบหมด ไม่ใช่ routing ดี
**ใช้ S5 (trained kmeans) เท่านั้น** · S4 K=64 ยิ่งแย่ (0.7485)

### 1.5 octfold — ใช้เป็น search index ไม่ได้
| หลักการ | ผล |

| P1 8-sector stride-3 เป็น anchor assign | recall **0.286** vs kmeans 0.924 (address-based, ยุบ) |
| P2 √2 scale ladder | ไม่มี cost win (hybrid-C พิสูจน์แล้ว) |
| P3 multi-view 2-of-3 | ได้เปรียบเล็กน้อย แต่ **ไม่ชนะ matched scan** |

**บทบาทจริง:** octfold = **STRIDE-3 view ของ ring-24** — ring เดียวกับ fan24 KIS wheel
(`FG_WHEEL_KIS=8`) → เป็น **carrier view / language** ไม่ใช่ index

### 1.6 quadtree×octfold hybrid — ตก

## 4. 💭 ทิศทางอนาคตที่คุยไว้ (ยังไม่ทำ — user แค่ประเมินความเป็นไปได้)

### 4.1 ANN layer = LoRA-analog
สถาปัตยกรรม **ต่อได้จริงทุกจุด** เพราะของมีอยู่แล้ว:

| ชิ้น | บทบาท | สถานะ |
|---|---|---|
| ANN layer (route/tombstone) | adapter ตัวเล็ก (256KB vs 300MB = 680×) | ✅ |
| `core/fan24_gear.h` | **sync transport** (Δ-only 1B/event, ENTER ANYWHERE) | ✅ 19/19 |
| `core/gguf_frustum_adapter.h` | **junction**: frustum route → tensor span | ✅ |
| CAPO | carry ข้ามโมเดล (bytes never move) | ✅ พิสูจน์แล้ว |
| `tools/geo_rid_graft.c` | RID slots → DtSlotRegion → llama.cpp | ✅ |

**ช่องว่าง:** ไม่มีโค้ด `ΔW / weight_delta / dissolve / apply_adapter`
→ ระบบมี transport + junction + carry ครบ แต่ขาด **experience → ΔW** (ตัว dissolve/upgrade)

### 4.2 Expert layer แทน/เสริม skill
**ระบบมี MoE expert layer อยู่แล้ว:**
- `core/moe_expert_addr.h` — expert_id = geometry coord = disk offset, **O(1) int-only**
- `core/moe_expert_store.h` — store/load บน DtSlotRegion
- `tools/moe_expert_stream.c` — stream เฉพาะ expert (top-4/64) + SwiGLU
- `tools/moe_expert_graft.c` — graft เข้า llama.cpp
- **test_moe_expert 30/30 PASS** · test_tess_moe_bridge ALL PASS
- capacity **6,912 experts** (20736/3 weight types)

**ข้อสรุปที่ user กับผมเห็นตรงกัน:**
- skill = **"รู้ว่า"** (knowing, text, portable, cheap, inspectable, กิน context)
- expert layer = **"ทำได้"** (being able, weight, 0 context, ฝังลึก, สร้างยาก)
- **ไม่ใช่การแทนที่ — เสริมกัน:** skill = แผนที่/safety net/ชั้นแก้เร็ว,
  expert = ชั้นฝังลึก · skill ใช้ซ้ำจนนิ่ง → **dissolve → expert** (= "training เป็น side effect")
- **จุดที่ยากที่สุด = error containment** (weight ผิดเสียทั้งโมเดล, ต้อง verify+rollback)
  ไม่ใช่แค่ขั้นตอนเยอะ
- **ข้อจำกัด:** expert layer ต้อง MoE จริง (dense model ต้องใช้ adapter/delta แทน)

**ตรงกับ END-GOAL memory:** *"Venom inherit จาก host ผ่าน bake→weight→cell map
แล้ว carry ข้ามโมเดลผ่าน 20736 + CAPO/adapter"*
