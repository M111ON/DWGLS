# Move Log → Compile — Constant Rules for the 3-layer manifest (2026-10-01)

## The claim (owner, 2026-09-30)

Three layers, not a compression pipeline:

```
MODEL WEIGHT  →  MORPH MAP  →  RUNTIME ADDRESS
```

`bake` runs **once** and emits a manifest of *travel rules* — not a recording of
the travel. The log's job is evidence and a manifest-building tool; it is never
a runtime dependency.

```
Move Log  →  Compile  →  Constant Rules + Tiny Fingerprint  →  Derive Address
```

The load-bearing question is not "can the chain collapse" but:

> If `Tfinal` is derivable from geometry/rules **without a per-element A→B
> table**, the whole shape holds. The moment we need a big X→Y table again, we
> are back dying at the old Beam permutation cost.

Flatten **the path**, not the model: the log is what gets flattened, into one
address transform (`logical A[1234]` → `field 7 / cell 42 / offset 19`), so the
runtime calls `ResolveFinalAddress` once instead of replaying
`jump1 → morph1 → jump2 → …`.

### Why this closure holds at all

Every hop in this system is affine-modular, `f(i) = (a·i + b) mod N`:

```
v6_slot(i) = (i·37) % 20736                        core/kis_codec_v6.h
frame_enc(t) = (t·37) % 1440                       core/geo_frame_seek.h:56-59
                                                  (FRAME_STRIDE 37, FRAME_CYCLE 1440, :8-9)
anch_slot(i, n) = (i·37) % n                       core/anchor_route.h:30-32
moe_expert_to_flat(...)                            core/moe_expert_addr.h
```

That class is **closed under composition**, so a whole chain stores as one
multiplier plus one offset. 37 is coprime with `20736 = 2^8·3^4`, so each hop is
a bijection and the composed map is invertible by rule.

### The validity condition is sufficient, not necessary

The collapse is guaranteed when the moduli are **nested**, `N(j+1) | N(j)`,
because then `(u mod N1) mod N2 == u mod N2` for every `u`.

Nesting is **sufficient, not necessary**. Brute force over small moduli
(155k cases, 1851 disagreements) found degenerate chains that collapse anyway —
e.g. `N1=2, a1=4, N2=4, a2=1` collapses because `a1·i` is always even. So
`chain_check()` uses the conservative test and **refuses the remainder**.
Over-refusing is the safe direction: an expanding hop that slipped through emits
a descriptor that *looks* like a clean bijection while pointing at slots the
chain never visited. That is the `beam_carry_xfield` shape — the value does not
get lost, the link dies, silently.

## The boundary — what is NOT proven

- **Real GGUF end-to-end bake.** T5 uses generated bytes. That is a complete
  proof *for the roundtrip* because every hop is value-blind and never reads the
  byte it moves (#6192), so the result cannot depend on byte content. It is
  **not** a proof of the bake-time layout **search**, which by construction does
  read values to measure residual.
- **A hop that reads values cannot be compiled.** `chain_compile()` assumes
  every hop is a pure function of position. If placement depends on the *value*
  of a byte — which is exactly what "search for the house with the most
  structure" means — there is no constant-size descriptor, and the step cannot
  leave the log. This is the same statement as the compression trap (#6198): a
  rule is compilable precisely because it never inspects what a byte means.
  Whether the bake-time search can be made position-only is **unresolved** and is
  the honest boundary of this whole approach.
- **The guard is sound but not complete.** `chain_check()` verifies
  `N(j-1) % N(j) == 0` for every `j`, so nested chains are provably safe and an
  expand-then-contract-back chain (`144→12→144`, caught by `12 % 144 != 0`) is
  refused. It may still refuse some chain that would have worked — the
  conservative direction.
- **Morph chains that change the index space.** The fold pyramid
  `20736→1728→144→12→1` is not affine-modular on the original linear index, so
  `Tfinal` becomes a short program of closed-form calls — still O(1), still no
  table, but **not** a single expression. Do not call it one.
- **`FINAL_LAYOUT` must end linear-contiguous per tensor.** llama.cpp's kernel
  reads tensors as linear bytes. A folded layout pays the unfold back at serve
  time and buys organization with zero tok/s.
- **Weight tying.** Qwen3 ties `lm_head = token_embd`, while llama.cpp creates a
  phantom F32 `output.weight` (#6211). A one-entry-per-logical-tensor manifest
  has to be able to state the tie or the resolver will silently build a second
  copy.

## The escape from a reduce hop: the quotient is free

A reduce hop throws away information. The expensive way to get it back is a
per-element fingerprint. The cheap way is to notice that the quotient was never
discarded — it is the other half of the address:

```
flat = q·144 + r          one divide yields both halves
apply the chain to r only → y ∈ [0,144)
(y, q) is injective over all 20736
```

T7 measures this: `W = TESS_CELLS = 144` (the same width `flat_to_tess` splits
on, cross-checked against `tess_to_flat`), `(y, q)` collision-free over the
whole field, and **`y` alone has only 144 distinct values** — the information was
genuinely lost, `q` is what recovers it, and it costs nothing to keep.

So the operative rule is: **never reduce across a wide window.** Reduce only into
a window the address is already aligned to.

### Why a per-element fingerprint is the wrong tool

| Cost | Value | Provenance |
|---|---|---|
| information destroyed by `20736→144` | `log2(144)` = **7.16993 bits/element** | derived (arithmetic) |
| in bytes | **0.89624 B/element** | derived |
| vs an int8 payload it would guard | **89.62 %** | derived |
| vs a closed Beam permutation cost | **55.6 %** | **UNVERIFIED** — the `1.612 B/element` Beam figure has no receipt in this repo; it came from an analysis pass on 2026-10-01. Do not cite it without re-deriving it. |

That is entropy that really was lost, paid back as metadata. It is not a receipt,
it is the bill.

## Proposed manifest fields

| Field | Status |
|---|---|
| `MODEL_ID` | trivial |
| `SHAPE_ID` | trivial |
| `FIELD_ID` | trivial |
| `JUMP_RULE` | **T7-proven**: constant-size descriptor + the free quotient |
| `RESIDUAL_FINGERPRINT` | **optional** — needed only for hops a rule cannot invert |
| `FINAL_LAYOUT` | constrained: must end linear-contiguous (see boundary) |
| `BLOCK` / `TENSOR TABLE` | one entry per logical tensor. Qwen3-4B-Q4_K_M has **398** tensors (`config.json` memory #6352), so at ~30 B/entry this is an **estimate of ~12 KB** — measure it once the fields are sized. Against a per-element table equal to the model size (4 GB at 4 B/element) that is **~333,000×**, i.e. 5.5 orders of magnitude. GGUF already carries a per-tensor table, so this is a small delta on structure that already exists. |

The fingerprint field is **optional, not mandatory**, and that is the whole
result of this investigation. Prefer a rule; pay for a fingerprint only where no
invertible rule exists.

## Hard rules

1. **Never write `27648 → 192` as a ratio anywhere.** 192 is the coordinate
   system of a one-block residual lane, not a compression result. Anyone who
   reads it as a ratio and tries to improve it walks straight back into the
   closed compression trap (#6198).
2. **Never re-introduce a per-element table.** If it cannot be derived from
   geometry/rules, the answer is a new hop or a new window width — not a table.
3. **A rule must be invertible by construction; the fingerprint only confirms you
   arrived.** The reverse path comes from the rule, never from the fingerprint.
   If one day we want to *search* for the return path from a fingerprint, we would
   need information the fingerprint does not hold: it answers right/wrong (one
   bit), not where-exactly-it-is-wrong (many bits).

## Prerequisite defects — found and FIXED 2026-10-01

Both were found while checking what already exists for the fingerprint lane, and
both are now closed with behavioural tests rather than bit roundtrips.

- **`rs_set_pinned()` added** to `core/residual_space.h`. `RS_ENTRY_PINNED` existed
  as a flag and the eviction paths at `:207` (in-line LRU) and `rs_evict_one` both
  honoured it, but **no API in the header could set it** — the only writer in the
  whole repo was `tests/test_rs_persist.c`, poking `e->flags` under a comment that
  said *"simulate pinned"*. Every production entry was therefore unpinned and
  evictable, so a Haunt jump table built on this store would have quietly lost
  points.
  Receipt: `unit_pin()` — 9 assertions. A pinned entry survives 199 further
  inserts into a 64-slot table with its payload byte-identical, and **unpinning
  makes it evictable again** (negative control, so "pin freezes everything" cannot
  pass). Mutation: making `rs_set_pinned` a no-op turns 3 of the 9 red.
- **Dead code removed.** `RS_EVICT_SCAN_WINDOW` (`"LRU eviction scan depth 64"`)
  was defined and referenced nowhere; `ResidualSpace.scan_pos` was declared and
  initialised to 0 and then never read. Both deleted. The remaining scan is
  `O(capacity)` but runs only when the table is full, i.e. once per `capacity`
  inserts — amortised `O(1)`, so the bounded window would have bought nothing and
  risked falsely reporting *all pinned* and refusing valid inserts.
  Removing `scan_pos` is format-safe: `rs_serialize` writes entries individually
  (`memcpy(p, e, RS_ENTRY_HEADER_SZ)`), never the `ResidualSpace` struct.

### Still open

- **`RS_ENTRY_REF`** (`"referenced by bond chain"`) is likewise set by no API —
  `tests/test_rs_persist.c` still pokes it directly. Informational only; nothing
  reads it, so it is not yet a hazard the way the pin flag was.
